## Decision, data and scope

The case assumes €2,500 incremental sales for a successful activation, €0 for a failed activation and €1,500 spend per activated store. The workbook label records whether an activated store generated *meaningful* incremental sales under the case definition. The workbook contains neither measured euro amounts nor a numeric cutoff for that label. Let `p` estimate the probability of this binary outcome conditional on activation. The financial assumption maps that probability to expected store net value `2500 * p - 1500`. With additive store values and the uncapped base case, maximize expected net by funding only stores with full-precision `p > 0.60`. A tie is unfunded, and an empty recommendation is valid. Use that probability comparison everywhere, including the release list and scenario flags, and round only for presentation. Common costs, margin and cross-store effects are outside the case model. [Group assignment, p. 1](Business%20and%20Marketing%20Analytics%20-%20Group%20Assignment.pdf#page=1) · [p. 3](Business%20and%20Marketing%20Analytics%20-%20Group%20Assignment.pdf#page=3)

| Test probability | Expected net per activation | Fund? |
|---|---:|---|
| 59% | −€25 | No |
| 60% | €0 | No |
| 61% | +€25 | Yes |

The five stratified folds, three model paths and approved all-480, repeat-eligible, uncapped base case come from the project specification. The seed, exact fold assignment, learner settings, calibration and stress bands, spatial split rules and comparison tolerances below are protocol choices. They are fixed for the primary run. Record and justify any later amendment before rerunning, and identify results from the amended protocol. [Project decision rules](SPEC.md#decision-rules-and-assumptions-for-approval)

Use Team 2's verified T06 snapshot and the [runbook](runbook.md). Require 480 unique national `Pdv Code` values, with 108 successes, 62 failures and 310 stores with unknown outcomes. Use only the 170 linked outcomes for training and validation. Map `incremental sales` to `y=1` and `no incremental sales` to `y=0`. Keep a nominal `success`/`failure` target for the learners. Retain raw IDs, lineage and coordinates in the audit table and keep them out of the learner inputs.

## Fixed, outcome-stratified folds

1. Canonicalize each numeric `Pdv Code` to its base-10 integer text with no decimal point, spaces or scientific notation. Export it as `store_id`. Check one row per ID in the labeled set.
2. Use fixed seed **20261120**. For each labeled ID, compute lowercase hexadecimal SHA-256 over the UTF-8 text `20261120:<store_id>`. In Java Snippet, bind the String input `store_id` and a String output `fold_key`. Hash the UTF-8 bytes with `java.security.MessageDigest.getInstance("SHA-256")` and render the digest with `java.util.HexFormat.of().formatHex(...)`. Handle `NoSuchAlgorithmException` as an execution error. The hash supplies a deterministic shuffled order independent of input order.
3. Split by outcome, sort each class by hash ascending and then `store_id` ascending, and assign a separate zero-based rank `r` to each sorted class. Set `fold = 1 + (r mod 5)` for successes and `fold = 1 + ((r + 3) mod 5)` for failures. The offset spreads the remainders across different folds. With the supplied inputs, the first three folds each have 22 successes and 12 failures, and the last two each have 21 successes and 13 failures.
4. Concatenate and sort by `store_id` as text. Export `outputs/folds.csv` with header `store_id,fold`, UTF-8 without BOM, no extra row ID or quoting, and LF line endings including the final line. Save its SHA-256. Independent Python and Node.js checks agree on all 170 assignments and produce reference digest `a5be2eeea3a41874ddb88db300c1f35fc9f7c052aab8f962a67f25b653ff9745` for those exact bytes. If a writer differs in formatting, compare the sorted assignments as well as the rerun hashes. Join this mapping once, by ID. Use a five-row **Table Creator** with integer column `k` containing 1 through 5 and **Table Row to Variable Loop Start** to expose it as a flow variable. In the loop, filter `fold=k` to test and its complement to train. Share these branches across all paths and sort training rows by `store_id` before fitting. Join the three scores on `store_id,fold` within the iteration, then use **Loop End** to collect the test rows. [KNIME loop reference](https://docs.knime.com/build/loops/reference)

## Predictors and fold-local preparation

All five source fields below are numeric and present for all 480 national stores in the inspected input. The shortlist covers catchment size, household resources and composition, and dental access while limiting model complexity for 170 labeled stores.

| Exact source field | Interpretation | Input transformation |
|---|---|---|
| `Total Population` | Catchment size | `ln(1 + x)` |
| `Avg Income per Household` | Catchment-level purchasing-power proxy | Identity |
| `Households avg components` | Average household size | Identity |
| `Nr of Hygienists` | Local dental-service availability proxy | `ln(1 + x)` |
| `Distance from a Dentist` | Dental access proxy in source units | `ln(1 + x)` |

Confirm units and plausibility in T05. Treat out-of-domain values, nonfinite values and unexpected text as data-quality exceptions. Zero is valid for a count. Before T08, record each predictor's source, reference period if known, and whether it would have been available before the 2026 activation and will be available when the 2027 list is set. The national file confirms coverage, but it has no field vintages. If source or timing cannot be established, label pre-activation availability as an unresolved assumption and treat performance as retrospective. If a feature uses post-activation or outcome information, exclude it from every path and split before any evaluation. Record the change. Restrict learner inputs to the allowlist and the nominal target. Coordinates are used for geographic validation and coverage.

Fit the following preparation on each training partition, in this order. Use the identical fitted parameters on its held-out rows or on the 310 unseen stores when training for release.

1. Apply the fixed row-wise input transforms. Calculate the median of available training values per field, then use it to impute missing entries in training and scoring. Drop a field if its training median is undefined or its training values after imputation are constant. Record the resulting feature mask. The five-field allowlist is the only planned feature selection beyond these training-only checks.
2. For logistic regression, center by the imputed training mean and divide by the imputed training **population** standard deviation. For the tree, use the transformed, imputed values without scaling. No categorical predictors are in the primary run. If a later approved variant introduces categories, fit the level dictionary and reference level in training and map unseen levels to an explicit unknown code before one-hot encoding. Fit any other feature selection inside each training partition.
3. In KNIME, compute medians with **GroupBy** on the training branch and broadcast its one-row statistics to both branches with **Cross Joiner**, then impute. Compute means and population standard deviations on the imputed training branch only. To implement the population denominator explicitly, aggregate the mean squared deviation from the training mean, then take the square root. Use **Expression** to apply the frozen statistics and use the same training-derived feature mask on both branches. Keep the input and output tables at the evaluation boundary on fixed schemas even if a learner's internal column set differs. If no features remain or a learner fails, flag the candidate and partition. A comparison requires all 170 predictions for each path. Never silently drop rows or substitute a different learner.

Example leakage check. In fold 2, take one hypothetical test store with missing income and unusually high population. Its income is filled using the median from the other four folds. Its transformed population is scored with the same training-only location and scale used for the other test rows. Its features and outcome are excluded from the median, scale, feature mask and learner fit. Its outcome is joined back after scoring for evaluation only.

| Leakage check | Enforcement |
|---|---|
| Split integrity and duplicate stores | Join on unique store ID, validate disjoint train/test IDs and require a one-to-one outcome join. A store appears once as test per model. |
| Imputation, scaling, encoding and selection | Fit all learned transforms and the feature mask on training. The primary allowlist is fixed and numeric. Never discover nominal predictor levels or select features before splitting. |
| Identifiers, linkage and outcomes | Explicitly include only transformed allowed predictors and the training target in learners. Carry IDs as row keys or side-table keys for reattachment. Drop outcomes from scoring tables. Keep join method, fold, coordinates and activation fields in audit tables. |
| Feature availability | The workbook has no dates for the five features. Record provenance and time availability as above before making a prospective claim. |
| Tuning, calibration and winner selection | No primary tuning or recalibration. Use nested training splits for approved follow-ups. The same OOF data choose and describe the model family, which leaves selection optimism even when each score excludes its own outcome. |

## Models and out-of-fold predictions

| Model | Fit and positive-class probability |
|---|---|
| Baseline | Aggregate the mean of `y` across the training rows. Broadcast that single success rate to the held-out rows. |
| Logistic regression | Use **Logistic Regression Learner** with `failure` as the reference class, an intercept, standardized predictors and the stochastic average gradient (SAG) solver. Enable **Hold data in memory** to avoid chunk-dependent optimization settings on these small tables. Use the fixed seed `20261120`, Gauss prior with variance 1, fixed learning rate 0.01, maximum 5,000 epochs and epsilon `1e-7`. Shrinkage stabilizes coefficients in a small sample. Use the `P(success)` output from **Logistic Regression Predictor**. Save warnings and inspect convergence before treating the results as valid. |
| Shallow decision tree | Use **Tree Ensemble Learner** with exactly **one** classification tree, row sampling disabled and no column subsampling. Use Gini splits, the node's depth limit 3 (setting 1 would give a stump), minimum split node size 20 and minimum child node size 10. Use numeric midpoint splits, no fixed root attribute, seed `20261120` and save target distributions. Use **Tree Ensemble Predictor** with individual class probabilities and soft voting. A single constrained tree allows interactions while limiting small leaves. Verify one tree and check on a sample prediction that the exported positive-class probability equals the leaf's success fraction. |

Use the fixed settings for the primary run. No class weighting, resampling, probability recalibration or threshold optimization is planned. If an approved follow-up tunes learner hyperparameters, use four inner outcome-stratified folds within each outer training partition. Reuse the seeded class sort with rank modulo 4 and a failure offset of `training_success_count mod 4`. Declare the candidate grid and tie order before fitting. Fit preprocessing independently on each inner training split. Score by pooled inner Brier. Refit the selected settings on the whole outer training set and score its untouched outer test set once. For the full-data refit, apply the same four-fold inner selection procedure to all 170 before fitting. A later proposal for recalibration requires a separate design: a mapping must be fitted on cross-fitted scores from the current training partition, and its performance must be evaluated on a disjoint assessment split. Training the mapping on the predictions it is evaluated on, or on scores obtained by fitting the base learner to the same observations, is invalid. [Varma and Simon, model-selection bias and nested cross-validation](https://pubmed.ncbi.nlm.nih.gov/16504092/)

For each fold and model, emit one probability in `[0,1]` per test ID. After **Loop End**, attach the actual outcome by a one-to-one join for evaluation. Export `outputs/baseline-oof.csv` (one row per labeled store with fold and baseline probability), `outputs/held-out.csv` (one row per labeled store with outcome, fold and all three probabilities) and `outputs/held-out-decisions.csv` (170 stores × 3 model paths). The latter includes ID, fold, model, probability, actual outcome, strict funding flag and realized net. Ignore any tree learner out-of-bag output for this protocol.

## Model comparison

- Report per model for each fold and pooled across all 170 cases. Include the test count, Brier score `mean((p-y)^2)`, funded count, funded successes and failures, realized sales, spend and net. Report the five fold results and their ranges. Aggregate pooled results directly from the held-out rows.
- Check local calibration in the fixed inclusive band **[0.55, 0.65]**. Report `n`, success count, average probability, observed success fraction and observed minus predicted difference. Report separately for **[0.55, 0.60]** and **(0.60, 0.65]** to show both sides of break-even. Mark empty bins unavailable and flag bins with fewer than ten observations as sparse. These are descriptive checks. At `n=10`, one outcome changes the observed rate by 10 percentage points, and even larger bins can be noisy. Ten observations or a small mean gap do not establish calibration. The overall band gap may cancel errors on opposite sides of the threshold. Avoid inferential claims from the bin gaps or fold ranges, given the overlap of training sets and possible spatial dependence. [Van Calster et al., calibration and sample size](https://link.springer.com/article/10.1186/s12916-019-1466-7)
- For an unfunded store, realized net is €0. For a funded success or failure it is respectively €1,000 or −€1,500. Compare with activate-all and activate-none on the **same** test IDs, both by fold and pooled. The respective pooled controls must be €15,000 and €0. Publish deltas versus both controls and versus the training-rate baseline path in `outputs/model-comparison.csv`.
- Independently computed ordinary-fold baseline check. The training success rates are `86/136` in folds 1–3 and `87/136` in folds 4–5. Each exceeds 0.60, so this baseline funds all 170 across the five test folds. It reproduces activate-all, with €4,000 net in each of folds 1–3 and €1,500 in each of folds 4–5. Pooled baseline Brier is approximately 0.231812284. These are analytic checks from the labels and fold counts.
- Choose between the two fitted candidates by higher pooled realized net. If their net values differ by less than €2,500, prefer lower pooled Brier if the difference is at least 0.01, otherwise prefer logistic regression for interpretability. The net tolerance is the value of one successful outcome at fixed spend, and the Brier tolerance avoids choosing on negligible probability-score differences.
- Treat deployment as a separate decision. Choose the strongest reference by pooled realized net among the baseline and all/none controls and compare against that same policy in all five folds. Ties between policies with different decisions favor activate-all, then the baseline, then activate-none for this diagnostic. Prefer a bounded pilot when the candidate fails to exceed the reference pooled, wins in fewer than three folds, or its advantage becomes nonpositive against the strongest spatial reference. Three fold wins is a stability heuristic. Flag an absolute calibration gap of at least 0.10 in any prespecified band or sub-band with at least ten observations, known coverage or provenance gaps, or a rollout conclusion that changes under the stress scenarios. Sparse checks leave expansion uncertain. The chosen candidate can still produce planning scores for a pilot.

## Geographic robustness

Run a separate leave-one-group-out check using the national workbook's latitude in decimal degrees. Hold out whole latitude bands, defined before inspecting performance. The three-band run tests broad geographic transfer using group boundaries fixed independently of the outcomes. Stores near opposite sides of a boundary can remain close, so describe this as a band holdout.

| Primary groups | Sparse fallback groups |
|---|---|
| South/islands band: latitude < 41.5° | Southern band: latitude < 43.0° |
| Central band: 41.5° ≤ latitude < 44.5° | Northern band: latitude ≥ 43.0° |
| Northern band: latitude ≥ 44.5° | — |

Use the three-band run only if each held-out band has at least 20 labeled stores and at least 5 of each outcome, and each training complement has at least 40 labeled stores and at least 10 of each outcome. These minimums retain some support for fitting both classes and evaluating their outcomes. If any band fails, use the predefined two-band fallback, with the same minimums. If the fallback fails, report group and class counts for both layouts, mark the comparison unavailable and use the labeled-versus-unlabeled coverage analysis to qualify transfer risk. Do not choose boundaries using model performance.

The primary southern band contains 34 successes and 4 failures, so the three-band split fails the minimum. The two-band fallback also fails: when the north is held out, the southern training complement has **46 successes / 5 failures**, below the required 10 failures. The north has **62 successes / 57 failures**. There are **167 unlabeled** southern and **143 unlabeled** northern stores. The qualifying geographic comparison is unavailable. Retain any already-computed band results as exploratory only. This corrects the earlier worked example, not the thresholds above. Neither ordinary CV nor this band holdout demonstrates performance at never-activated sites.

For each viable spatial split refit all preparation and both candidates using the other group(s). Recompute the training-rate baseline and all/none controls on the same spatial test IDs. Report the same metrics by band and pooled, and compare the direction of the net-value advantage with ordinary cross-validation. Compare labeled versus unlabeled store counts and predictor distributions by primary band with T07. Geographic transfer among the historical activations leaves uncertainty about stores never activated. Keep spatial probabilities separate from the primary fold and national score exports.

## National scoring, sensitivity and same-spend comparison

Refit the chosen specification on all 170 labels with the same training preparation and fixed settings. Score the 310 unseen stores with this fit. Use the chosen model's original out-of-fold probabilities for the 170 historical stores. Concatenate the two disjoint score sets. Write `outputs/national-scores.csv` with one row per `store_id`, `p_success`, `score_source` (`held_out_2026` or `refit_unseen`), unrounded `expected_net_eur` and `recommend_activate`. Filter on the flag for `outputs/activation-list.csv`. Keep both exports sorted by ID and preserve full probability precision. Report selected counts, spend and forecast net by score source as well as pooled. The 136-row fold fits and 170-row full fit can produce different score distributions, so a pooled ranking mixes training sizes and selection histories. The repeat-170 benchmark uses one score source. The optimized list can use both. This affects the interpretation of both Size of Prize comparisons.

Compute expected sales as `2500 * sum(p)`, spend as `1500 * N`, and expected net as their difference. Show forecast optimized net less realized 2026 net (€15,000), and forecast optimized net less a forecast repeat of the original 170 IDs. Use the same national score for each store wherever it appears.

- **Stress scenarios.** Use membership in the original **[0.55, 0.65]** band for both scenarios. For band members use `max(0, p - 0.05)` and `min(1, p + 0.05)`. Keep other probabilities fixed. Use decimal arithmetic for the shift and comparison (for example, start with `BigDecimal.valueOf(p)` in Java Snippet) to preserve exact ties at 0.60. Export per-store scenario scores, net, flags and added/dropped IDs in `outputs/sensitivity.csv`. Report lower, base and upper counts, spend and forecast net. Identify stores selected throughout this test and those whose funding changes. This is a local stress test. It provides no confidence interval and does not probe forecast errors outside the band or a broader change in the success rate.
- **When to compare at equal spend.** Trigger a scale check when `abs(N - 170) >= 17`, a 10% or €25,500 difference in activation spend. Also show the matched-count comparison for any `N < 170`, so the shortfall is visible even below the trigger.
- **How to match counts.** Set `k = min(N, 170)`. Rank the positive-value optimized list by descending unrounded probability, with ascending text `store_id` for ties. Take its first `k` IDs. Independently take the `k` highest-scored historical IDs from the repeat-170 list using the same scores and tie-breaker. Forecast both at spend `1500 * k` and show the net difference. Choosing the strongest forecast subset of the repeat campaign makes this a demanding reference within the model. Since the optimized ranking can choose from the full universe, its matched-count forecast is at least as high by construction. That difference quantifies what the model expects at equal spend and provides no independent evidence of targeting lift. Repeat IDs may overlap with optimized IDs and can have nonpositive value in the comparator. The actual plan keeps all and only the qualifying stores under the uncapped base case. If `k=0`, both matched-size campaigns have zero spend and net, and lift at positive spend is unavailable.

Activation in 2026 was selective. T07 should report feature distributions and support by label availability. In the supplied files, five unseen stores are outside the labeled income range, two outside the population range and two outside the household-size range. Counts can overlap. Range checks can miss differences within ranges and in combinations. Geography and unobserved retailer choices may affect who was activated and how they responded. Historical tests therefore describe the labeled sample under the case economics. Year-to-year stability and transport to the other stores remain assumptions. Predictions cannot identify treatment effects, shopper preferences or share lift. Reporting the candidate chosen on the same outer results can be optimistic even when preprocessing and individual predictions are fold-local. An evaluation of the entire selection procedure would repeat family selection inside each outer training set or use independent data. The 2027 forecast also selects on estimated values, so funded stores near break-even and their aggregate net are sensitive to scoring error. A controlled pilot can supply evidence on expansion.

## Amendment, 26 Nov 2026: Random Forest release

The team selected the five-feature Random Forest (100 trees, Gini, seed 2026, hard voting) as the scorer
([issue #51](https://github.com/MoriondoTommaso/P-G_marketing_campaign/issues/51)). The forest was not one of the two candidates in this protocol, so extending the
economic criterion to a third family is a retrospective amendment. In the final workflow the forest's test-fold
scores are used for the 170 historical stores and a forest refit on all 170 scores the 310. Every published score is
the exact vote share (success votes ÷ 100), and a store is funded only with more than 60 of 100 votes, so a 60-vote
tie is unfunded, as required above. The three models share the same X-Partitioner folds (identical settings and input);
the hash-based ID folds and the input-order checks are not implemented in the class workflow and are tracked in #51.
